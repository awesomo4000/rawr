# Spec 21-01: Fused count-only cardinality gallop kernel

Second chunk of [skewed `andCardinality`](21-skewed-andcardinality.md). **Authored around
`21-00`'s attribution**, which is now known: the ~1.43x full-API skewed `andCardinality` gap
is essentially the **galloping-count kernel** (forced-gallop 75.561 vs 42.968 ns/container =
1.76x; traversal + dispatch at parity), and it **generalizes** across ratios and mixed cases.
This chunk closes it.

> **Done (2026-07-23, commit `5dae1e1`) — gap closed.** The fused cached-cursor state machine
> replaced the generic `gallopSearch` + per-value equality check (count-only path; write
> kernels, dispatch, thresholds untouched). M4: **75.561 → 43.426 ns/container (= CRoaring)**;
> full API both 0.014 ms. Zen 4: rawr 41.958 vs CR 42.755 ns/container, full API rawr 0.009 vs
> CR 0.008 ms. Empty/singleton/reversed-argument tests, `bench_aa`, CRoaring differential, and
> both build modes green on M4 **and** Zen 4.

## Mechanism

rawr's `intersectCardGallop` (`src/array_kernels.zig`) walks each small-side value and calls
the **generic lower-bound `gallopSearch`** plus a **separate equality check** per value.
CRoaring's `intersect_skewed_uint16_cardinality` uses a **fused, cached-cursor `advanceUntil`
loop**: advance the large-side position to the first element ≥ the value, count a hit when
equal, carry the cursor forward — inline, no separate lower-bound + equality step per value.

Implement a **fused count-only cardinality loop** for the skewed array path mirroring that —
a cached-cursor advance that counts hits inline — replacing the generic-gallop + equality
check in `intersectCardGallop`.

## Scope / constraints

- **Count-only path only** (`intersectCardGallop`). The write gallop (`intersectWriteGallop`)
  is **out of scope** here; if `21-00`'s data suggests the same pattern there, note it as a
  possible follow-up — do not change it in this chunk.
- **Dispatch and thresholds unchanged.** `21-00` showed selection is at parity; this is a
  **kernel** change, not a threshold re-tune.
- **Architecture: shared kernel → x86 validated natively.** `intersectCardGallop` is the
  scalar galloping path used across architectures (not a NEON-SIMD kernel), so per spec 21's
  scoping rule a change here is a **shared-kernel change**. Validate it by **native testing on
  the x86-64 / Zen 4 host** — running the tests and the diagnostic matrix, **not** merely a
  successful cross-compile. (Confirm the arch structure in the source; if it is arch-split,
  test each variant touched.)
- **Correctness:** `andCardinality` result unchanged (`== |a ∩ b|`); the array-kernel
  differential coverage (`bench_aa` cross-checks gallop / merge / SIMD for identical results)
  stays green.
- **Explicit edge-case tests** — the fused cached-cursor loop is prone to cursor / off-by-one
  errors, and current cardinality tests do **not** cover empty arrays. Add tests for: **empty
  inputs** (one side empty, both empty), **singleton arrays** (small and/or large side of size
  1), and **reversed argument order** (`andCardinality(a, b) == andCardinality(b, a)`).
- **No regression** at other skew ratios, on the balanced-array kernels (spec 11), or on the
  write path.

## Acceptance (GO)

- The forced-gallop cardinality kernel **ns/container moves materially toward CRoaring's
  ~43** (from 75.561), and the full-API 32 × 4096 skewed `andCardinality` **moves toward
  parity** (from 1.43x), measured in the isolated fresh-process focused executable, five runs,
  median + range.
- The improvement **holds across `21-00`'s generalization-matrix points** and overlap
  distributions — not just 32 × 4096 all-hit.
- Differential green and **natively validated on the x86-64 / Zen 4 host** (shared kernel —
  tests + diagnostic matrix, not just compiled); full build green under `ReleaseSafe` and
  `ReleaseFast`.
- Validation: `zig build test`; `zig build bench-aa -Dcpu=native && ./zig-out/bin/bench_aa`;
  `zig build difftest`; `scripts/run-bench-parity-isolated.sh` (the isolated five-process
  parity result); and `scripts/run-bench-and-cardinality-diag.sh` to confirm the kernel
  ns/container moved toward ~43.
- Given the ~6 µs absolute, **closing most of the kernel gap is success**; full parity is a
  bonus and a documented partial is acceptable — do not over-invest.
