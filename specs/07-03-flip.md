# Spec 07-03: flip (range complement)

Third piece of the [CRoaring parity effort](07-parity-inventory.md). rawr has **no
flip** today; it's a common op. Flip toggles membership of every value in a range
— present→absent, absent→present — leaving everything outside the range untouched.

Marked "needs design" in the inventory, but it largely collapses: **flip over a
range is exactly XOR with that range** (`flip(lo,hi) = self △ range[lo,hi]`), so it
reuses rawr's already-tested XOR machinery and its container create/destroy logic.
Recommended impl is the identity; a direct per-container negation is an optional
perf follow-up.

## Features

| rawr (new) | CRoaring | Semantics |
|---|---|---|
| `flip(allocator, lo, hi)` | `roaring_bitmap_flip_closed` | new bitmap = self with `[lo, hi]` complemented |
| `flipInplace(lo, hi)` | `roaring_bitmap_flip_inplace_closed` | complement `[lo, hi]` in place |

**Range convention:** inclusive both ends, matching rawr's `addRange`. Map to
CRoaring's `*_closed` (inclusive) oracle to avoid the exclusive-end `+1` dance.
Provide `flipOwned` to match the existing `*Owned` API surface.

## Task 0 — Wrapper decls

Add to `vendor/croaring_wrapper.h`:

```c
roaring_bitmap_t* roaring_bitmap_flip_closed(const roaring_bitmap_t*, uint32_t lo, uint32_t hi);
void              roaring_bitmap_flip_inplace_closed(roaring_bitmap_t*, uint32_t lo, uint32_t hi);
```

## Task 1 — Implementation (identity-based, recommended)

`flip(lo, hi)` over a bitmap toggles exactly the bits in `[lo, hi]`, which is
`self XOR M` where `M` is a bitmap with exactly `[lo, hi]` set. XOR already
handles container creation (chunks where self is empty but `M` isn't), destruction
(chunks emptied by the toggle), and type transitions — so this is correct by
construction and rides the XOR differential coverage from spec 01.

```zig
pub fn flipInplace(self: *Self, lo: u32, hi: u32) !void {
    if (lo > hi) return;                 // empty range: no-op
    var mask = try RoaringBitmap.init(self.allocator);
    defer mask.deinit();
    _ = try mask.addRange(lo, hi);       // inclusive, matches convention
    try self.bitwiseXorInPlace(&mask);
}

pub fn flip(self: *const Self, allocator: std.mem.Allocator, lo: u32, hi: u32) !Self {
    var result = try self.clone(allocator);
    errdefer result.deinit();
    try result.flipInplace(lo, hi);
    return result;
}
```

(Plus `flipOwned` mirroring the other `*Owned` wrappers.) Watch the leak-checked
allocator: the temporary `mask` must be freed on every path (the `defer` covers
it).

**Edge cases to handle:** `lo > hi` → no-op; `lo == hi` → single-value toggle;
range spanning many chunks including currently-empty chunks (XOR creates them);
range that exactly fills/empties a chunk (container created/dropped). All of these
fall out of XOR + `addRange`, but they're the differential cases to test.

## Task 1b — Direct per-container negation (optional perf follow-up)

The identity allocates a full range mask `M`, which for a wide range is many full
bitset chunks. CRoaring flips per-container without materializing the mask. If the
Task 6 bench shows the mask allocation hurts on wide ranges, add a direct path:
per affected chunk, negate the low-16 sub-range in place (interior full chunks =
full negation → empty drops the container, empty fills to a full container;
boundary chunks = partial negation), re-deriving the optimal container type
(`bitsetToArrayOrRun`). Keep it behind the same public API; the identity stays as
the correctness reference in tests. **Not required for this spec to land** —
correctness first, optimize if measured.

## Task 2 — Differential checks (`diff_test.zig`)

flip produces a bitmap → use `assertAgree` against `roaring_bitmap_flip_closed`.
Over the mixed generator, both `run_optimize` states:

1. **Within one chunk:** flip a sub-range of a populated chunk (array, bitset, and
   run profiles) → assertAgree.
2. **Full chunk:** flip `[k*65536, k*65536+65535]` over a populated chunk and over
   an **empty** chunk (creates a full container) → assertAgree.
3. **Cross-chunk range:** flip a range spanning several chunks, including chunks
   that are currently empty in self → assertAgree.
4. **Whole-domain-ish & boundaries:** ranges touching `0`, `65535`, `65536`, and
   `lo == hi`; `lo > hi` no-op.
5. **In-place == allocating:** assert `flipInplace(clone, lo, hi)` equals
   `flip(self, lo, hi)` (same cross-check pattern the set-op matrix uses).
6. Add a flip case (random range) to the **randomized loop**.

## Task 6 — Benchmark vs CRoaring (moderate, optional but recommended)

flip over a **wide** range on a dense bitmap is memory-bandwidth bound (like
`addRange`). Add a `bench_croaring.zig` comparison of a wide-range flip vs
`roaring_bitmap_flip_closed` and record the ratio. This is also the signal for
whether Task 1b (direct negation) is worth doing.

## Acceptance criteria

1. `flip`, `flipInplace`, `flipOwned` exist with the inclusive-range convention.
2. Results match `roaring_bitmap_flip_closed` across within-chunk, full-chunk
   (populated and empty), cross-chunk, and boundary/`lo==hi`/`lo>hi` cases, both
   run-optimized and not.
3. `flipInplace` == allocating `flip`; flip added to the randomized loop.
4. No leaks (temporary mask freed on all paths) under the leak-checking allocator.
5. `zig build test`, `zig build validate`, `zig build difftest` pass.
