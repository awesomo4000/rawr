# Spec 25-01: M4 cluster — fix (conditional on `25-00`)

Second chunk of [M4 bitset-kernel codegen cluster](25-m4-bitset-codegen.md). **Authored around
`25-00`'s attribution** — no lever preselected here.

## Gate

- `25-00` complete: each row attributed to a component + cause (or named residual), with the
  shared-cause verdict, on both hosts, and enough evidence to choose a fix or a NO-GO. If the
  rows are independent M4 quirks with no clean fix, this chunk is **not written** (NO-GO).

## Lever — follows `25-00`

- **Inline popcount (eager dense AND/OR):** split rawr's bitset ops into **card / no-card
  variants** (compute cardinality only when the caller needs it, as CRoaring does), or defer it —
  preserving the `-1` cached-cardinality invariant. One change, potentially multiple rows.
- **`VEC_SIZE` width:** a **per-arch** comptime width (or a restructure that lowers cleanly on
  aarch64).
- **Mask-based range-op component** (flip/removeRange): fix the implicated part — vectorize the
  aarch64 `toggleRange`/`clearRange` word loop, avoid the clone, or defer the cardinality
  recompute.
- Rows that don't share the cause get their own component fix.

## Constraints

- **Must not regress Zen 4** (rawr is at/ahead there) — a per-arch change or one neutral-to-better
  on x86; verified on both hosts.
- **Correctness:** bitset results **and** cardinality stay correct — differential green including
  cardinality after every op and the cache-invalidation invariant. A card/no-card split must not
  leave a stale cached cardinality (audit every caller that reads `cached_cardinality` after an op
  that now skips the popcount).
- Production kernel change, differential-covered; existing op semantics unchanged.

## Acceptance

- The affected rows reach **≤ 1.10x on M4** with **no regression on Zen 4**, and no other
  canonical row worsening >5% vs the **latest committed corrected parity baseline** (rerun on
  range overlap); differential green including cardinality.
- A **partial** improvement (some rows closed, others documented as no-clean-fix) is an acceptable
  terminal outcome — record which rows moved and which didn't.
- Validation: `zig build test`; `zig build difftest`; canonical `run-compare-bench.sh` on both
  hosts; `ReleaseSafe` / `ReleaseFast` green.
