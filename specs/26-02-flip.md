# Spec 26-02: Direct `flipInplace`, by-value `flip`, and `flipOwned`

Third chunk of [direct range ops](26-direct-range-ops.md). Replaces the clone-plus-mask
composition (`flip` deep-clones the whole bitmap, `src/bitmap.zig:1139`; `flipInplace` builds a
mask bitmap and XORs it in place, `:1642`) with direct construction, behind `26-00`'s strategy
seam.

## Gate

- `26-00` complete. (`26-01` is not a dependency, but shared partition/walk helpers should be
  reused if it landed first.)

## Design (per the parent contracts)

- **Chunk partition** as in `26-01` (full edge chunks are interior; overflow-safe walk).
- **`flipInplace`:** untouched containers stay; edge containers flip a sub-range in-container
  (sanctioned range-view into `containerXorInPlace`, or per-type `toggleRange`-based helpers —
  whichever meets byte equality); interior existing containers flip whole (conversion /
  drop-if-empty per the kernels' thresholds); **missing interior chunks** become full-range
  1-run containers. **Reserve the upper bound** (current containers + missing covered chunk
  keys) before the first mutation so commit-phase inserts cannot fail. One compaction.
- **`flip` (by-value):** construct the result directly — clone only untouched containers, build
  flipped containers for affected chunks. **No whole-bitmap clone, no mask bitmap.** Full
  cleanup on error (`errdefer`), input untouched. `flip(lo > hi)` returns an **independent
  clone** (today's behavior). `flipOwned` rides the same path.
- **OOM (in-place):** the two sanctioned models (mutate-then-fallible-convert leaves the valid
  mutated container installed; separate replacements build-then-swap).
- **Cache:** `flip`/`flipInplace` **invalidate to `-1` before the first committed mutation**;
  every path — success or failure — leaves the cache invalidated, never stale.

## Acceptance

- `26-00` harness: direct-vs-legacy **byte equality** across the full matrix + CRoaring parity
  (`flip_closed` oracle), both strategy settings, for all three entry points.
- **Exhaustive allocation-failure injection** on `flipInplace` (incl. failures during
  missing-chunk insertion and conversions): `validate()` green, cache `-1`, leak-free. By-value
  `flip` failure paths leak-free with input untouched.
- **Allocation counts:** whole-bitmap clone and mask-bitmap allocations gone; report vs
  baseline.
- Semantics unchanged; `zig build test`, `zig build difftest`, `ReleaseSafe`, `ReleaseFast`
  green. Performance gated in `26-03`.
