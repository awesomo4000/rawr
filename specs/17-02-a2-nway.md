# Spec 17-02: A2 — local-arena n-way prototype (dense no-regression)

Third chunk of the [transient-bitset arena](17-transient-bitset-arena.md) Phase A.
Builds experiment **A2** on the `17-00` harness: a benchmark-only n-way prototype whose
arena lifetime is fully local, to show the transient arena **helps the sparse-heavy
n-way case and does not regress the dense case** — the workload lazy union actually
exists for.

## What it is

A **separate benchmark-only function** (not an edit to `manyMerge`) that models
`manyMerge`'s enclosed construct-then-repair shape with a transient allocator for
guaranteed-demote key groups. `manyMerge` already repairs internally, so the arena's
lifetime is naturally local here — no escaping result, no ownership machinery. Production
`manyMerge` is untouched.

## Behavior

- **n-way eligibility prepass:** for each shared key group, accumulate the same-key input
  cardinality sum in `u64` (or early-saturating at 4096) **before** allocating the
  accumulator. Arena-eligible only when the complete bound is **known ≤ 4096**; any input
  bitset with stored `cardinality < 0` makes the group ineligible; no fresh cardinality
  scan to qualify.
- **Allocation granularity / kernels:** eligible group → whole temporary
  `BitsetContainer` from the transient allocator, demoted array on the persistent
  allocator; ineligible group → current path unchanged. Reuse the production accumulation
  (`setList`) and demotion kernels; eligibility, allocator source, and lifetime are the
  only differences.
- **Variants:** baseline (current path), `ArenaAllocator`, exactly sized
  `FixedBufferAllocator` (slab from a count of actual eligible groups). Teardown inside
  the combined timed region.

## Workloads (both required, from `17-00`)

- **Sparse-heavy n-way** — many shared keys with per-key summed bound ≤ 4096, so the
  arena is genuinely exercised. This must show a win.
- **Dense n-way control** — shared keys summing above 4096, all bypassing the arena. This
  must not regress: it is the check that the guaranteed-demote gate keeps dense on the
  existing path (no transient-then-persistent double allocation or 8 KB copy).

## Acceptance

- **Value parity:** each variant byte-identical to rawr's current n-way path on both
  workloads; logically equal (set + cardinality) to the CRoaring oracle.
- **Leak-free** under a leak-checking GPA on both workloads (eligible + ineligible group
  mixes).
- **Eligibility fires:** the harness's eligibility count confirms the sparse-heavy
  workload actually routes groups through the arena, and the dense control routes ~none.
- **Timing:** sparse-heavy shows a win for at least one transient variant (report which);
  **dense control combined within the measured noise band** vs baseline.
- **Memory:** peak child-allocator live (size-class) bytes ≤ **110%** of baseline on both
  workloads.
- Benchmark-only; full build green under `ReleaseSafe` and `ReleaseFast`.

## Result to record

The A2 sparse-heavy win number and the dense-control regression figure (with noise band)
— the other half of the Phase-A go/no-go input. Together with `17-01`'s ceiling, this
decides whether Phase B (the escaping arena-backed result) is attempted at all.
